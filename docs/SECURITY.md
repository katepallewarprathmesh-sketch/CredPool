# Security review

Review date: 2026-10-03

## Automated checks

- Solidity compiler 0.8.24 with optimizer and via-IR: pass
- Hardhat acceptance/integration tests: pass
- Solidity coverage: 100% statements and lines; branch report generated by `npm run coverage`
- Slither: **not executed in this workspace because the `slither` binary is unavailable**. Run `slither . --config-file slither.config.json` in CI before a public deployment. No claim of a clean Slither result is made.
- npm audit reports transitive findings in the local Hardhat toolchain. The separately installed frontend reports zero vulnerabilities. Audit and pin the deployment toolchain before release.

## Controls reviewed

- EIP-712 domain binds attestations to chain ID and AccessBadge address.
- Per-subject monotonically increasing nonces prevent replay.
- OpenZeppelin ECDSA rejects malformed/high-s signatures.
- The issuer is checked both at claim time and every time credential validity is queried.
- Removing an issuer immediately disables credentials without iterating holders.
- Badges reject holder-to-holder transfers in the ERC-1155 `_update` hook.
- Registry anchoring is limited to `BADGE_ROLE`; revocation is issuer-or-admin only.
- Pool entry points use `ReentrancyGuard`, checks-effects-interactions, and `SafeERC20`.
- Fee-on-transfer assets are explicitly rejected using balance deltas.
- Slippage and deadline protections are enforced.
- The first 1,000 LP units are permanently locked.
- Pausing blocks swaps/deposits but intentionally leaves verified withdrawals open.
- No PII is stored on-chain. VC payloads are encrypted before content-addressed storage.

## Known limitations

1. This is unaudited demonstration software; do not use it with production funds.
2. Admin and issuer roles are powerful. A production deployment should use separate multisigs and delayed role changes.
3. Tier limits use the pool reserve ratio for token1-to-token0 equivalence and can therefore be influenced by pool price manipulation.
4. The AMM has no oracle, TWAP, sandwich protection, or concentrated liquidity.
5. The development storage adapter emulates encrypted content-addressed persistence on local disk; a production Pinata/Helia adapter and availability policy are still required.
6. The mock KYC passcode is deliberately non-secure.
7. LP tokens are transferable to unverified accounts, but those accounts cannot redeem until they hold a valid Pro credential.
8. Credential replacement invalidates the old credential for access but does not mark its historical record revoked.
9. Emergency withdrawals still require a valid credential, matching the specification. Governance should define a disaster-recovery policy for issuer outages.
10. Sepolia deployment and Etherscan verification require operator-supplied credentials and have not been performed in this workspace.

## Recommended release gates

- Run Slither and document every high/medium result.
- Commission an independent audit.
- Add multisig addresses and a role-management runbook.
- Add CI for compile, tests, coverage threshold, frontend build, Slither, and dependency scanning.
- Exercise Sepolia deployment, verification, issuer rotation, and incident recovery.
